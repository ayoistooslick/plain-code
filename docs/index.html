Introduction

What is PLINJS?

PLINJS is an Intent-Oriented Programming Language (IOPL). It compiles .pln source files to JavaScript and runs them with Node.js. PLINJS’s design goal is to let developers describe what they want to happen in near-English sentences, while the compiler handles the JavaScript implementation details.

Intent, not implementation

Write what you want to happen, not how JavaScript should do it. The compiler bridges the gap, generating clean, readable JS output.

Zero configuration

No webpack. No tsconfig. No babel. Drop a .pln file anywhere and run it. Zero configuration required.

One way to do everything

No decision fatigue. PLINJS has exactly one way to declare a variable, one way to loop, one way to define a function. Less syntax to memorise, more time to build.

Errors that teach

Every error message tells you what went wrong, which line, and — when possible — exactly what to type instead. The compiler is a tutor, not a gatekeeper.

npm-compatible

Any npm package can be declared with use and installed with plinjs add. The entire Node.js ecosystem is one keyword away.

Code that reads like docs

PLINJS code doubles as documentation. Hand it to a non-programmer and they will understand it. That constraint makes your code better for everyone.

What PLINJS is NOT

PLINJS is not a natural-language prompt system. You cannot type free-form English and have it compile. Every construct in PLINJS is defined by explicit syntax and precise semantics. The language reads like English because it was designed that way — not because an AI is interpreting your intent at compile time. PLINJS is a real programming language with a deterministic compiler.

Installation

Install PLINJS

PLINJS is a Node.js package. Install it globally and you’re ready to compile .pln files anywhere on your system.

Install locally via npm
npm install --save-dev plinjs
Requirements

Node.js 16+ is required. PLINJS works on Windows, macOS, and Linux. No other dependencies are needed.

WhatsApp

WhatsApp Bots

Link a real WhatsApp account by QR scan or pairing code and answer messages in near-English. Baileys powers it behind the scenes — detected and installed automatically, never imported in your source.

bot.pln 
whatsapp bot
    auth "session"
    login pairing "2348012345678"

    on message
        log message

        if message.text is "/start"
            reply "Welcome! Send /help for commands."
        done

        // Backtick strings keep line breaks…
        if message.text is "/help"
            reply `Available commands:
/start - greet you
/help - this message`
        done
    done
done
Generated JavaScript (excerpt) 
// Baileys runtime emitted by the compiler;
// the package is installed for you at build time.
const { __whatsappStart,
        __whatsappOnMessage,
        __whatsappReply } = (() => {
  /* makeWASocket, useMultiFileAuthState … */
})();

await __whatsappStart({
    folder: "session",
    login: { mode: 'pairing', phone: "2348012345678" }
});

__whatsappOnMessage(async (__waCtx) => {
    console.log(__waCtx.message);
    if (__waCtx.message.text === "/start") {
        await __whatsappReply(__waCtx.chat,
            "Welcome! Send /help for commands.");
    }
});

Linking a device

The first run prints either a QR code to render in your terminal or a pairing code like D4PN-RX5C to type into WhatsApp → Settings → Linked Devices → Link with phone number instead. Credentials are saved to your auth folder, so every later run reconnects silently until the device is unlinked.

Lifecycle details

Your own outgoing messages and status broadcasts are filtered out of handlers. Unexpected disconnects auto-reconnect after ~3 seconds; a deliberately logged-out device stops cleanly with a clear error. Phone numbers are validated at compile time (8–15 digits).

Vision

OCR — read text out of images

One sentence extracts text from scans, screenshots, and photos. Tesseract.js does the work; PLINJS keeps it out of your source.

ocr.pln 
// Extract text — mirrors ask "... as name"
ocr "scan.png" as text
show text

// Pick a language pack (default: "eng")
ocr "brief.png" as inhalt using "deu"
show inhalt

// Combine packs, use any expression as the image
remember shot as "receipts/receipt-01.png"
ocr shot as total using "deu+eng"

if total contains "INVOICE"
    show "invoice detected"
done
Generated JavaScript 
const { createWorker } = require('tesseract.js');

async function __ocr(imagePath, lang) {
    const worker = await createWorker(lang || 'eng');
    try {
        const { data } = await worker.recognize(imagePath);
        return data.text;
    } finally {
        await worker.terminate();
    }
}

let text = await __ocr("scan.png", "eng");
console.log(text);

Forms

PLINJSBehavior

... using "<lang>"Tesseract language pack: "deu", "deu+eng", …
tesseract.js stays out of your source

The implementation dependency is wired automatically: plinjs install, plinjs run, and plinjs build detect ocr statements and fetch tesseract.js for you. The statement is async like ask — top-level use wraps the program, and using it inside a function makes that function async.

Aliases & version ranges

Hyphenated and scoped names can now bind to a variable with as <name>, and any specifier may carry a version range (@^1.3.0, @~2, @*). Ranges flow through to installation; require() always uses the bare name. Aliasing PLINJS’s built-in runtime packages (express, sqlite, …) produces a friendly error instead of silent breakage.

Automatic runtime dependencies

PLINJS detects use, web app, ocr, and database dependencies. plinjs install, plinjs run, and plinjs build install only missing npm packages — checked by bare name, installed with their full name@range specifier. Built-in Node modules are never installed.

Portable databases

database "app.db" probes the native driver and falls back to WebAssembly SQLite (sql.js). Pin it with using "native" or using "wasm".

Passwords and tokens

scrypt hashing with hashPassword/checkPassword; HMAC-signed tokens with expiry via createToken/readToken.

File uploads

accept uploads limit "5 MB" allow [...] folder "..."; files surface as records with name, type, size, data and path (HTTP 413/415 enforced).

Rate limiting and API keys

limit requests to 100 per minute per-IP sliding window; require api key from env("API_KEY") fails closed.

Google OAuth

A google oauth block registers redirect and callback endpoints and stores the signed-in user on the session.

Error handling and retries

try ... recover ... done catches failures; retry 3 times every 5 seconds re-runs flaky operations until they succeed.

Security

Security Model

PLINJS compiles deterministically — the JavaScript you run is the JavaScript you can read. The compiler adds multiple layers of validation so projects stay safe and predictable.

Readable output

Every construct compiles to plain, inspectable JavaScript. Nothing hidden, nothing generated behind your back — plinjs build shows you exactly what will run.

Dependency restrictions

Packages referenced by use must be declared and installed. Missing dependencies stop compilation with a friendly error instead of failing at runtime.

Teaching errors

The compiler rejects ambiguous or invalid programs at compile time with clear messages — including route-only features used outside routes and sessions used without enable sessions.

Environment secrets

API keys and tokens are read from environment variables via env() at runtime. Secret values never live in PLINJS source code.

.env support

PLINJS loads .env files automatically via dotenv. Environment variables are available through env("KEY") in PLINJS code.

Hardened web primitives

Passwords use salted scrypt with constant-time verification, tokens are HMAC-signed with expiry, API-key checks fail closed, and sessions ride HttpOnly cookies.

    reply "Todo API running"

Fetching Multiple APIs

multi-fetch.pln 
remember users as await fetch "https://jsonplaceholder.typicode.com/users"
remember posts as await fetch "https://jsonplaceholder.typicode.com/posts"

if users is ok and posts is ok
    remember userData as users.json()
    remember postData as posts.json()
    show "Users: " + length(userData)
    show "Posts: " + length(postData)
otherwise
    show "One or more API calls failed"
done

Database-backed API

db-api.pln 
web app
database "app.db"

execute
    CREATE TABLE IF NOT EXISTS items (
        id   INTEGER PRIMARY KEY,
        name TEXT NOT NULL
    )
done

route "/items"
    remember rows as query
        SELECT * FROM items
    done
    reply json
        items is rows
    done
done

start 3000

FAQ

Frequently Asked Questions

PLINJS is an Intent-Oriented Programming Language (IOPL). It compiles .pln source files to JavaScript and runs them with Node.js. PLINJS’s design goal is to let developers describe what they want to happen in near-English sentences, while the compiler handles the JavaScript implementation details.
PLINJS 0.1.7 includes runtime dependency detection, automatic installation, OCR, npm aliases and version ranges, portable databases, an HTTP client, sessions, uploads, rate limiting, deployment-oriented CLI commands, WhatsApp bots, and interactive terminal input — backed by a test suite of 625 checks. It compiles to standard Node.js-compatible JavaScript and remains well-suited for personal projects, tooling, and learning.

Yes. Any npm package can be declared with use <package> and installed with plinjs add <package>. PLINJS scans your source files for use declarations and manages the underlying node_modules automatically, validating that all declared packages are installed before compiling.

An optional using "<lang>" clause selects a language pack ("deu", "deu+eng", …); extraction defaults to English.

Open Source

Contributing

PLINJS is open-source and welcomes contributions. Whether it’s a bug report, a test case, a documentation fix, or a new feature — every contribution matters.

Report a bug

Found something that compiles incorrectly or crashes? Open an issue on GitHub with a minimal .pln reproduction.

Write a test

Tests live in tests/compiler.test.js. Adding a test for an edge case is one of the most valuable contributions.

Submit a pull request

Fork the repo, make your change, and run node tests/compiler.test.js. The full compiler and runtime suite must pass before merging.

GitHub repository

Source code, issues, and pull requests at github.com/ayoistooslick/plain-code. Read CONTRIBUTING.md before opening a PR.
