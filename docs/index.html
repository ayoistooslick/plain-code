Philosophy

Why Plain?

Most programming languages were designed by and for computer scientists. Plain was designed to be understood by anyone who can write a sentence.

Intent, not implementation

Write what you want to happen, not how JavaScript should do it. The compiler bridges the gap, generating clean, readable JS output.

Zero configuration

No webpack. No tsconfig. No babel. Drop a .pln file anywhere and run it. Configuration is optional and stored in a single plain.json.

One way to do everything

No decision fatigue. Plain has exactly one way to declare a variable, one way to loop, one way to define a function. Less syntax to memorise, more time to build.

Errors that teach

Every error message tells you what went wrong, which line, and — when possible — exactly what to type instead. The compiler is a tutor, not a gatekeeper.

npm-compatible

Any npm package can be declared with use and installed with plain add. The entire Node.js ecosystem is one keyword away.

Code that reads like docs

Plain code doubles as documentation. Hand it to a non-programmer and they will understand it. That constraint makes your code better for everyone.

Features

Everything you need. Nothing you don’t.

Plain ships with batteries included — a full standard library, built-in web and database support, a formatter, and a VS Code extension.

English Keywords

Every keyword — remember, becomes, show, make, give — was chosen to mirror plain English. No symbol soup.

Built-in Web DX

First-class Express integration with web app, route, reply json, and start. Build REST APIs in a dozen lines.

Built-in SQLite DX

Write SQL inline with query, insert, update, delete, and execute blocks. Powered by better-sqlite3.

Standard Library

20+ built-in functions for I/O, strings, numbers, files, time, JSON, and UUID — all available with no import statement.

Auto Formatter

One command formats your entire .pln file with consistent 4-space indentation, proper spacing, and normalised blank lines.

VS Code Extension

Syntax highlighting, snippets, bracket matching, comment toggling, and code folding — all for .pln files out of the box.

Setup

Quick Start

Plain compiles .pln files to JavaScript and runs them with Node.js. No bundlers, no transpilers, no configuration required.

Install globally via npm
npm install -g @ayoxx/plain-code

Create a new project

Terminal 
$ plain new myapp
$ cd myapp
$ plain install
$ plain start

Your first Plain program

hello.pln 
remember name as "World"
show "Hello, " + name

make greet(person)
    show "Nice to meet you, " + person
done

greet(name)
Generated JavaScript 
let name = "World";
console.log("Hello, " + name);

function greet(person) {
    console.log("Nice to meet you, " + person);
}

greet(name);

Essential commands

plain check

Validate syntax without compiling or running. Exits 0 on success, 1 on error. Ideal for CI pipelines.

plain fmt

Auto-format your .pln file in-place with consistent 4-space indentation and normalised spacing.

plain add

Install an npm package and add it to plain.json automatically. Try plain add express.

plain build

Compile to .js without executing. Inspect the generated JavaScript to understand what Plain does.

plain run

Compile and immediately execute a .pln file. The output is printed to the terminal as it runs.

plain new

Scaffold a new Plain project with app.pln, plain.json, and a .gitignore already set up.

Plain Expressions v1.1

Collections, properties, and files read like sentences. The compiler generates the JavaScript for you.

Plain 
remember players as ["Haaland", "Foden", "Rodri"]

show first player from players
show last player from players
show player two from players

show players length
add("Palmer" to players)
remove("Rodri" from players)

show name of user
name of user becomes "Ayo"
JavaScript 
let players = ["Haaland", "Foden", "Rodri"];

console.log(players[0]);
console.log(players[players.length - 1]);
console.log(players[1]);

console.log(players.length);
players.push("Palmer");
players.splice(players.indexOf("Rodri"), 1);

console.log(user.name);
user.name = "Ayo";
How it works

Number words one through twenty pick items by position: player one from players is the first player. of chains right-to-left, so city of address of customer reads customer.address.city. Files use read("users.txt") and write(data to "users.txt"). All v1.0 syntax still works.

JavaScript Gateway v1.1.1

Run raw JavaScript blocks, read input with ask, and use any npm package — including hyphenated and scoped names.

Plain 
remember response as javascript
    const res = await fetch("https://api.example.com")
    const data = await res.json()
    return data
done

ask "What is your name?" as name
show "Hello, " + name

use node-fetch
use @scope/package-name
How it compiles 
let response = await (async () => {
    const res = await fetch("https://api.example.com")
    const data = await res.json()
    return data
})();

let name = await __ask("What is your name?");
console.log("Hello, " + name);

require('node-fetch');
require('@scope/package-name');
How it works

JavaScript block bodies are passed through verbatim and wrapped in an async function whose result becomes the variable. ask reads a line from the terminal using a built-in readline runtime. Hyphenated and scoped package names are not valid JavaScript identifiers, so they compile to a bare require('...').

Imports

Split a project across multiple .pln files using relative paths.

app.pln 
import "./math.pln"
import "./utils.pln"

show add(3, 4)
Import rules

Paths must be relative (./ or ../). Files compile in dependency order — deepest first. Circular imports produce a friendly compiler error.

Automatic runtime dependencies

Plain detects use, web app, and database dependencies. plain install, plain run, and plain build install only missing npm packages; built-in Node modules are never installed.

v2.0

AI-Assisted Compilation

The deterministic compiler stays authoritative. When it cannot compile a supported construct, versioned rules and an AI provider translate it into validated JavaScript that flows through the normal bundler/runtime path.

telegram.pln 
remember token as env("BOT_TOKEN")

remember bot as telegram bot with token

when someone sends "/start"
    reply "Hello from Plain!"
done
http.pln 
remember response as await fetch "https://facts.com"

if response is ok
    remember data as response.json()
    show data
otherwise
    show "api failed"
done

Rule system

Versioned rule pairs (Markdown + JSON) for Telegram bots, HTTP fetch, and REST APIs live in compiler/rules/ and ship with the package.

Validated output

AI-generated JavaScript is syntax-checked and scanned for forbidden patterns and undeclared requires before it can run.

Secrets protected

Configuration is environment-based (MISTRAL_API_KEY, PLAIN_AI_BASE_URL, PLAIN_AI_MODEL). Secret values are never sent to the provider.

Local cache

Successful translations are cached locally, keyed by rule version + compiler version + model + source. Stale rules are never reused.

Diagnostics

Run plain ai status, plain ai rules, or plain ai cache [clear]. See docs/AI_COMPILATION.md for the full guide.

Database

SQLite Developer Experience

Inline SQL blocks compile directly to better-sqlite3 calls. No ORM. No query builder. Just SQL written naturally inside your Plain program.

database.pln 
database "app.db"

execute
    CREATE TABLE IF NOT EXISTS users (
        id   INTEGER PRIMARY KEY,
        name TEXT NOT NULL,
        age  INTEGER
    )
done

insert
    INSERT INTO users (name, age)
    VALUES ('Alice', 28)
done

query
    SELECT * FROM users ORDER BY name
done

update
    UPDATE users SET age = 29
    WHERE name = 'Alice'
done

delete
    DELETE FROM users WHERE id = 1
done

SQL block reference

PlainCompiles to
database "file.db"const db = new Database("file.db")
query … donedb.prepare(`…`).all()
insert … donedb.prepare(`…`).run()
update … donedb.prepare(`…`).run()
delete … donedb.prepare(`…`).run()
execute … donedb.exec(`…`)
Classic style also works

You can also use sqlite and call sqlite("database.db") directly if you prefer the classic approach.

Zero configuration

SQLite files are created automatically if they don’t exist. No server to start, no credentials to manage.

Automatic Code Formatting

plain fmt formats your .pln file in-place. One command, no options — consistent code across every project.

Before formatting 
remember   x as  10
if x is above 5
show "big"

otherwise
  show "small"
done
After plain fmt 
remember x as 10

if x is above 5
    show "big"
otherwise
    show "small"
done

Formatting rules

4-space indentation

All block bodies — if, while, for each, make, route — are indented with exactly 4 spaces.

Trailing whitespace removed

Every line has trailing spaces stripped. The file ends with exactly one newline.

Blank lines normalised

One blank line between top-level blocks. Multiple consecutive blank lines are collapsed into one.

Open Source

Contributing

Plain is open-source and welcomes contributions. Whether it’s a bug report, a test case, a documentation fix, or a new feature — every contribution matters.

Report a bug

Found something that compiles incorrectly or crashes? Open an issue on GitHub with a minimal .pln reproduction.

Write a test

Tests live in tests/compiler.test.js. Adding a test for an edge case is one of the most valuable contributions.

Submit a pull request

Fork the repo, make your change, and run node tests/compiler.test.js. The full compiler and runtime suite must pass before merging.

GitHub repository

Source code, issues, and pull requests at github.com/ayoistooslick/plain-code. Read CONTRIBUTING.md before opening a PR.
