Transform Plain-Code into its new compiler identity: PLIN.

This is NOT a cosmetic rename. Treat PLIN as a new npm package/project identity while preserving the .pln language extension and existing language semantics.

VERSION
- New npm package name: plin
- Start the new package at 0.1.7 using SemVer.
- Remove @ayoxx/plain-code as the package identity throughout the project.
- Update package metadata, CLI output, imports, documentation, tests, examples, release metadata, and all user-facing branding from Plain-Code/plain-code to PLIN where appropriate.
- Do not rewrite historical changelog entries unnecessarily; preserve history where it is explicitly historical.

COMPILER / BUILD MODEL
Replace the old temporary-output model with a TypeScript-style production build model.

`plin build` must:
- deterministically compile .pln source files to JavaScript
- write output to `dist/` by default
- preserve source filenames

Example:
    messi.pln
    plin build

produces:
    dist/messi.js

NOT:
    dist/index.js
    _plain_out.js

Remove the `_plain_out.js` runtime/build model entirely.

PACKAGE.JSON
Projects should use normal Node package.json.

Example:

{
  "scripts": {
    "build": "plin build",
    "start": "node dist/index.js"
  },
  "devDependencies": {
    "plin": "^0.1.7"
  }
}

`plin build` must work when PLIN is installed locally through npm and invoked through npm scripts.

Do not require users to globally install PLIN for deployment.

CONFIGURATION
Design and implement a deterministic PLIN project configuration file, preferably `plin.config.json` unless the existing architecture strongly suggests another name.

It must allow users to configure at minimum:
- source location / entry files where appropriate
- output directory, default `dist`
- output structure
- package/build mode where needed

Example:

{
  "outDir": "dist"
}

and:

{
  "outDir": "build"
}

The compiler must preserve source filenames relative to the configured source root.

Do not overengineer the config system yet.

NPM PACKAGE BUILDING
PLIN must be capable of building npm packages written in .pln.

Support a project structure such as:

package.json
src/
    index.pln

and produce a normal Node-compatible package build:

dist/
    index.js

The resulting package must be usable by npm consumers without requiring them to understand PLIN internals.

Preserve package.json semantics and ensure generated JavaScript, package exports, dependencies, and entry points can work as a normal Node package.

Do not invent a PLIN-specific package registry or package format.

IMPORTANT
- Keep `.pln` as the source extension.
- Keep the deterministic compiler as the only compiler.
- Complex Compilation must remain deleted.
- Do not reintroduce AI compilation.
- Do not weaken existing syntax validation.
- Do not break existing PLIN language features.
- Do not hardcode `index.js` as the output filename.
- Do not hardcode `dist` internally where configuration should control it.
- Add deterministic compiler tests for every new build/configuration behavior.
- Add integration tests for building a multi-file project and an npm-package-style project.
- Update documentation only after the implementation and tests pass.

Run the full test suite and relevant real build tests.

Do not commit or push.
