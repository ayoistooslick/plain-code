CURRENT PROBLEM

We tested all 3 existing rules through the hosted /translate endpoint.

Telegram:
- The AI generated incompatible node-telegram-bot-api code because the installed package version/API is different from the old examples.
- The environment currently uses node-telegram-bot-api 2.x, whose CommonJS export exposes `Bot`, not the old `TelegramBot` constructor.
- A working direct Node test was:

  const { Bot } = require("node-telegram-bot-api");

  const token = process.env.BOT_TOKEN;
  if (!token) {
    throw new Error("BOT_TOKEN is not set");
  }

  const bot = new Bot(token);

  bot.command("start", (ctx) => {
    return ctx.reply("Baaaka");
  });

  bot.on("message", (ctx) => {
    console.log("Received:", ctx.message?.text);
  });

  bot.startPolling().catch((err) => {
    console.error("Polling failed:", err);
  });

This successfully started and received Telegram messages.

HTTP Fetch:
A request like:

  remember response as await fetch "https://httpbin.org/get"

was translated into JavaScript containing top-level `await`, but the validator rejected it with:

  await is only valid in async functions and the top level bodies of modules

The fetch rule currently says `"async": true` and claims that the Plain runtime wrapper provides top-level await, but the hosted AI output is being validated before the necessary async wrapping occurs.

REST API:
The basic REST rule currently works. We tested:

  remember app as express app

  app get "/health" as
      reply "ok"
  done

  listen app on port 3000

and the hosted compiler returned valid JavaScript:

  const express = require("express");
  const app = express();

  app.get("/health", (req, res) => {
    res.send("ok");
  });

  app.listen(3000);

Do NOT break this working behavior.
